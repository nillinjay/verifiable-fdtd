## How a reader tells a declared-absent gap from a real pass, in one line

Every verdict prints a greppable one-liner (`leg27-evidence:` prefix):

```console
leg27-evidence: leg15 present -- leg15-closure-latest-run-cases: present at runs/<run>/readout.json
  (newest of 1, 14 usable case(s)); skip guards: checks/test_leg15_closure.py:145
leg27-evidence: leg12 declared-absent -- leg12-slab-run-with-monitor-arrays: nothing matched;
  skip guards: checks/test_leg15_closure.py:83, 107, 118, 131, 153
leg27-evidence: leg4 needed-absent -- …; skip guards: …      ← the one that fails the run
```

`present` is a real pass; `declared-absent` is a visible-but-accepted gap (the line names the leg
and the guards that will skip); `needed-absent` fails the exit status. On a healthy machine (the
owner's `main` workspace, where the archives exist) the check prints `present` per leg and exits 0.

## Design notes this leg states, not silently substitutes

1. **Where the absence flag lives.** The pinned design says "the owning leg's config carries
   `evidence_absent_by_design: true`", but `configs/` is outside this leg's write set, so the flag
   is read from the owning leg's *entry in the declaration config*
   (`checks/evidence_requirements.json`, per-leg `evidence_absent_by_design`), each entry recording
   its `owning_config` pointer (`configs/leg4-convergence-ladder.json`, `leg11-coverage-audit.json`,
   `leg12-closed-slab.json`, `leg15-closure.json`). Stated so the steward can move the flag into
   the `configs/` files later without another leg.
2. **The built-in inventory is the structure authority.** With the declaration file absent
   (origin/main today), the check can still name every leg and path — that is why the inventory is
   built-in and the JSON is validated against it, rather than the JSON being the only source.
3. **`LEG27_DECLARATIONS`** overrides where the declaration file is read from (documented above).
   It cannot change what the predicates require; it exists to reproduce A1 on any later tree.
4. **The fixture npz is force-added.** `.gitignore` ignores `*.npz` globally (for real run data).
   The probe npz is 322 bytes of one marker array, force-added
   (`git add -f checks/fixtures/…/slab-sample-monitors.npz`) so the negative control survives in a
   fresh clone. It is never opened by the check — only its existence is asserted — and nothing
   loads it as data.
5. **Known limitation:** a future guard written as a `@unittest.skipIf(...)`/`raise SkipTest(...)`
   *decorator* with a `no archived …` reason is scanned too, but a guard that skips without any of
   the scanned call shapes (e.g. a custom helper) would evade the scan layer; the declaration-side
   predicates would still catch the absent artefact, but the scan would not name the new site.
   Re-derive the inventory when a leg adds archive-dependent guards in exotic shapes.
