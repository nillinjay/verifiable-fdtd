# LEG 28 — a missing reference contract must be a declared refusal, not a traceback

Date: 2026-10-20. Branch `leg28-preflight-reference-policy`, base `origin/main` at `cb02db5`
(the LEG 28 registration commit). This is a **test leg**: the only files written are
`checks/test_preflight_reference_policy.py` and this document. `checks/pre_environment.py` is
untouched. CPU only: no `./tools/run.sh`, no GPU, no resource lock, nothing imported from
`src/torchfdtd`.

## The defect

`checks/pre_environment.py:99-100` enters the reference branch with

```python
if config['kind'] == 'alignment' or config.get('reference'):
    from reference_contract import load_reference
```

and the import sits **outside** the `try` that opens at `checks/pre_environment.py:101`. No
`reference_contract.py` exists anywhere in the repository (`git ls-files` and `find . -name
'reference_contract*'` both return nothing; `.venv/bin/python -B -c "import reference_contract"`
raises `ModuleNotFoundError`). The refusal at `checks/pre_environment.py:102-105` is written
carefully for an **invalid** reference, but the missing-**module** case never reaches it.

Measured against this worktree before the test file existed, with a temporary config:

```

```

The negative control (an `audit` config that needs no reference) pre-flights normally:

## The pinned policy this test encodes

When the reference contract cannot be imported, pre-flight exits **`65`** and its message names,
in this order:

1. that the reference contract module is **missing** (not that a reference file is invalid);
2. the config field that required it (`kind: alignment`, or `reference`);
3. that **no simulation was run**.

The test drives `checks/pre_environment.py` in a **subprocess**, because the defect is that the
process dies; importing the module and poking it would not reproduce it. Every config is a
temporary file under `tempfile.TemporaryDirectory()`. The child environment drops
`PARITY_CONFIG`, `PARITY_SOLVER_ROOT`, `PARITY_SOLVER_UPSTREAM` and `PARITY_SOLVER_ROLE` so the
gate resolves the tracked relative roots in `configs/baseline-pin.json` and is not steered by the
caller's shell. Nothing under `configs/`, `runs/` or `output/` is read or written, and no
reference file is fabricated.

### What each assertion requires

`assert_declared_refusal` requires, on the combined stdout/stderr of the child:

- exit status exactly `65`;
- **no** `Traceback (most recent call last)` and **no** `ModuleNotFoundError` — a declared refusal,
  not a leaked exception;
- a missing-contract phrase and the literal token `reference_contract` (fact 1);
- for `kind: alignment`, `kind` followed within 20 characters by `alignment`; for a `reference`
  field, a field/key construction such as `config field 'reference'`, `'reference' key`, or
  `config['reference']` (fact 2);
- `no simulation` (fact 3);
- the three matches in the pinned order fact 1 < fact 2 < fact 3.

Test 4 additionally requires that the missing-contract output contains **none** of the
invalid-reference vocabulary (`reference unavailable/invalid`, `invalid reference`, `reference
unavailable`), so a reader can tell the two refusals apart.

## What the pinned policy says that this leg could not test, and why

- **The invalid-reference refusal itself is not executed.** Reaching
  `checks/pre_environment.py:102-105` requires a successful import of `reference_contract`, and
  the stop conditions forbid creating that module (inventing a reference schema is an invented
  input). Test 4 therefore asserts **message-level distinguishability**: the new missing-contract
  refusal must not use the invalid-reference vocabulary. If the implementation leg later adds the
  module, a follow-up test can compare the two run outputs directly.
- **The brief's premise that the invalid-reference path "already exits 65" is not what the code
  does.** `checks/pre_environment.py:104` raises `SystemExit(<message string>)`, and Python exits
  `1` for a string argument to `SystemExit` (it prints the string to stderr); only an integer
  argument carries a status. Measured with a throwaway stub module under `/tmp` (not in the
  repository): the invalid-reference branch prints
  `staircase reference unavailable/invalid: stub-invalid; no simulation allowed; see
  output/lumerical-reference-contract.md` and exits **1**. This matters for the implementation
  leg: the missing-contract refusal must use `raise SystemExit(65)` or `sys.exit(65)` (or an
  equivalent), not `SystemExit(message)`, or it will exit 1 and tests 1, 2 and 4 stay red.
