# LEG 31: stop worker failures without rewriting shared solver source

## Outcome and acceptance limit

The LEG 19 driver now stops on every worker failure, records the worker exit
status, and returns that status without restoring solver source or retrying the
worker. The out-of-memory status remains 59. The non-out-of-memory control uses
57 and remains 57. No simulation, launcher invocation, or GPU allocation was
needed for this change.

A1, A2, and A3 have passing evidence below. The initial A4 run exited 1 because
the frozen LEG 23 test required the now-prohibited restoration. The steward
subsequently authorized a narrow contract change to that test on the authority
of the independent review's R4 MUST. With that change, the exact full-suite
command exits **0**: 373 tests, no failures or errors, and 15 skips. The initial
failure and authorization are recorded below. This worktree still has no copied
archived run directories, so the evidence-present part of A4 remains unverified;
final acceptance belongs to the steward.

## Scope and implementation

The starting project commit was `513de05` on `leg31-no-fork-rewrite`, with a
clean working tree. The contract is `plan.md` under LEG 31. The branch changes
only the four files named there plus `checks/test_leg23_reserved_gate.py`,

## A1: real decision, failing before and passing after

`checks/test_leg31_no_fork_rewrite_on_oom.py` calls the real
`leg19_admission.main()` worker-exit decision. It does not reimplement the
decision in the test and does not construct a solver or a git repository.
Workers are replaced by controlled exit results. Earlier successful workers
produce only the minimal report fields needed to reach each decision.

The test observes write-mode `Path.open` calls under an absent temporary solver
path. An attempted write is recorded and contained in an in-memory stream, so
the original bug can reach the assertion without writing any solver file. A
spy on `subprocess.check_output` also requires that no restore-source command
be attempted. Worker-command assertions allow only the expected worker calls.
The test checks that execution stops at the first failure, preserves its exit
status in both the return value and report, and records no `C4_reversion`.

The seven worker positions tested are `old-2`, `frozen-2`, `new-0`, `new-1`,
`new-2`, `low-budget-2`, and `occupied-2`. This covers both sides of the old
variant condition as well as every position that used to trigger restoration.

Before changing the driver or configuration, this command ran against the old
decision and exited **1**:

```sh
.venv/bin/python -B -m unittest checks.test_leg31_no_fork_rewrite_on_oom -v
```

It ran two test methods. The non-OOM control passed for all seven positions.
The OOM method produced five failing subtests: each of the three `new`
positions, `low-budget`, and `occupied` attempted exactly one fork write. The
`old` and `frozen` OOM positions made no write, as the original condition
predicts. Each failure was on the intended assertion, for example:

```text

```

After removing restoration, the same command exited **0**, ran two methods
in 0.021 seconds, and passed all 14 worker-exit scenarios. Every printed

```sh

That process exited **0**, running one method with seven subtests in 0.011
seconds. All simulated worker exits of **59** returned driver exit **59**.

## Authorized LEG 23 contract change and final A4 result

The steward then explicitly added `checks/test_leg23_reserved_gate.py` to the
write set, authorizing only the assertions whose premise changed and a name
that describes the new contract. This is a **contract change authorized by the
steward on the independent review's authority**, not an implementation fitted
to its own test. The authority is finding R4, severity MUST, in
`reviews/batch-1-wave-2-2026-10-19.md`: restoring the old shared solver file
erases LEG 25's own-demand fix and leaves the LEG 22 plane call incompatible
with the restored estimator.

At the time LEG 23 shipped, its policy called for reverting the candidate
admission change after an OOM. Accordingly, line 126 asserted that the working
source equaled the committed pre-change `original`; line 128 required a clean
working tree; and line 131 required a successful `C4_reversion` record. R4
retired that premise because later legs share and extend the same source.
These three assertions now require the existing candidate bytes to remain,
the original modified-file status to remain, and no `C4_reversion` entry.
The historical sentinel text and temporary repository setup are retained.

The method is renamed from
`test_actual_oom_revert_branch_only_writes_temporary_repository` to
`test_actual_oom_branch_preserves_temporary_repository`. The file description,
one explanatory comment, and printed outcome now describe stopping and
preservation. The rest of the fixture and checks are unchanged. In particular,
all seven `ReservedRelation` tests retain their refusal, missing-measurement,
boundary, and reserved-underprediction negative-control coverage. The OOM test
still checks exit 59, no retry or later worker, unchanged HEAD, and the saved
failure status. None of that unrelated coverage is removed.

The changed assertion would fail if OOM restored the pre-change file or wrote
any different source bytes. To demonstrate that it can fail, the pre-fix
driver was loaded from `git show 513de05:src/leg19_admission.py` into an isolated
Python namespace; `patch.object(checks.legacy, 'main', baseline['main'])`
supplied its real decision to the renamed test. The repository source was not
reverted for this check. The test exited **1** in 0.007 seconds, failing at
line 126 with the pre-change sentinel instead of the candidate bytes. Its
temporary repository contained the old behavior; the live solver was never
used. Preservation alone does not detect a transient write followed by a
restoration of identical candidate bytes; A1's existing write-attempt observer
continues to check that stricter no-write contract directly.

Against the fixed driver,
`.venv/bin/python -B -m unittest checks.test_leg23_reserved_gate -v`
exited **0**: all eight tests passed in 0.008 seconds. The retained negative
control still printed gate failure with exit 57 for reserved underprediction.
The exact A4 command was then rerun without filters or skip changes:

```

Its process exit was **0**, with zero failures and zero errors. The test count

Only `runs/ledger.jsonl` is present in this worktree's `runs/`; no archived run
