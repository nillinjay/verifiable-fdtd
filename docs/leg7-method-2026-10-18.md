# Leg 7 — the method question, settled by arithmetic — 2026-10-18

After part 2 was rejected, the owner chose to settle the method question **by arithmetic before
another campaign**. This file records what that arithmetic settles. **No simulation ran.**

## The question

Part 2 failed with a reconstruction error of `0.1783` against a tolerance of `0.05`. Three candidate
causes were recorded:

1. the source must span the beam, so a one-cell source is too small;
2. the comparison target is wrong: a one-cell aperture diffracts, it does not make a `w0` Gaussian;
3. the monitor is too close, so the periodic replicas have not decohered.

## The answer: none of the three. The weights are right, and the cell index was mapped wrong.

The Array Scanning Method's weights live in the **cell index**:

    a_n = (1/M) * sum_m A(k_m) exp(i k_m n d),   A(k) = exp(-k^2 w0^2 / 4)

`a_n` is the M-point **inverse transform** of the sampled spectrum, so `n` is a **circular** index.
Its physical position is the **centred** mapping `x = (n - M//2) d`, which puts the source at the
middle of the valid window `|x| < M d / 2`.

Mapped naively as `x = n d` for `n = 0 .. M-1`, the window covers only the **right half** of the
beam. That is the failure signature: the reconstruction error barely moves when `M` rises.

| `M` | window half-width | relative envelope error, **centred** | relative envelope error, **naive** |
|---|---|---|---|
| `8` | `+-3.60` µm | `2.41e-02` | `0.685` |
| `12` | `+-5.40` µm | `4.11e-04` | — |
| `16` | `+-7.20` µm | `1.75e-06` | `0.687` |
| `24` | `+-10.80` µm | `1.41e-06` | — |
| `32` | `+-14.40` µm | `1.59e-06` | — |

**The centred mapping converges. The naive mapping does not**, and it does not improve with `M` —
exactly the behaviour the campaign showed.

## What this says about each candidate

1. **"The source must span the beam" is wrong.** The source stays **one cell wide**. The beam width
   comes from the weights `a_n`, which spread the source over `M` cells. That is what the method
   does, and it is why `M` is the cost.
2. **"The comparison target is wrong" is wrong too.** The reconstruction *is* the Gaussian sampled
   at cell centres, so comparing against the ideal Gaussian is right — provided the mapping is
   centred.
3. **"The monitor is too close" is not established.** Nothing here points at the monitor distance,
   and moving it would hide the real defect rather than fix it.

## What is still open, and is NOT explained by this

The **energy gate** is a separate failure and remains open: the soft source delivered `39 percent`
less power at the zone edge than at normal incidence. The linear-combination premise needs the
response per unit source amplitude to be angle independent. Attempt 3 divided by the square root of
the delivered power and moved the reconstruction error by `2 percent`, so the normalisation is not
that simple, but the corrected cell mapping may change that conclusion. **The energy spread must be
explained before the campaign is run again.**

## Consequence for the next attempt

1. centre the cell index; the arithmetic in `src/oblique_asm.py::cell_weights` now does this and is
   covered by tests;
2. keep the source one cell wide;
3. still explain the `39 percent` delivered-power spread.
