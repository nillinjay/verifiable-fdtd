## 1. Wiring fix (`src/invariants.py`)

`V2-a` covered only the `R` and `T` leaves. In this leg it also covers the two scalar energy fields
its arithmetic determines. Neither one is granted by its name.

* **`energy_residual`** is the stored copy of `max|R+T-1|`. It is covered only when it is
  **bit-identical** to the closure `V2-a` has just recomputed from `R` and `T`. The basis for using
  exact equality: it is the same float64 expression, and JSON round-trips a float64 exactly. If the
  stored copy differs, it goes into `rejected`, its label is forced to `unchecked`, and the reason
  says "a stored residual is not trusted".
* **`empty_reflection_floor`** is a measured flux ratio: the matched empty reference's flux through
  the plane behind the one-way source, divided by the reference denominator. That is the one exit
  that `R+T` does not count. `V2-a`'s premise "every exit monitored" holds only if this leakage is
  within the same budget. So it **enters the `V2-a` error** (`error = max(closure, floor)`), and
  it is covered because it entered that error. A non-finite floor fails the check.

Effect on archived reports. I compared mechanically against `HEAD`'s `invariants.py` over all 39
run directories. **37 are byte-identical.** The leg-2 run `20261018T054325Z-241687` changed in 13
lines: `energy_residual` and `empty_reflection_floor` went `unchecked → verified V2-a`, and the
`V2-a` error went from `0.0` to `1.6805e-13` (the floor; still under `1e-12`). No other label
changed. The remaining changed run is this leg's own new run.

**What this tightens:** `V2-a` is now strictly stricter than in leg 2, because a leaky reference
fails it. It cannot newly pass anything it failed before.

## 2. Non-empty closed box (`src/leg12_closed_box.py`, `configs/leg12-closed-slab.json`)

The same closed box as leg 2 (periodic transverse walls, both x exits monitored), with a
lossless index-3.5 slab inside. The slab inputs are leg 3's `analytic-slab` values. The tolerance is
**kept at leg 2's `1e-12`**, because stop condition 2 forbids widening it.

| case | what | `max|R+T-1|` | floor | `V2-a` | `V2-b` |
|---|---|---|---|---|---|
| `slab` | lossless, 260 fs | `7.508e-7` | `7.18e-14` | **failed** | passed (0) |
| `slab-long` | lossless, 520 fs | `7.442e-7` | `7.18e-14` | **failed** | passed (0) |
| `lossy-control` | Lorentz slab (solver defaults, `epsilon_inf = 3.5²`) | `0.3403` | `7.18e-14` | dropped as unlawful (declared lossy); **negative control: failed** | — |

**Stop condition 2 was triggered.** The measured floor of the lossless non-empty box is
**`7.5e-7`**. What is known about its cause:

* It is **not time truncation**. Doubling the duration moves it by 1 percent (`7.51e-7 → 7.44e-7`).
* It is **not mesh-limited at first order**. Leg 4's ladder already recorded the slab residual at
  ppw 20/40/80/160 as `7.54/7.51/7.38/7.31e-7`, which is almost flat.
* It is **not loss**. It is two-signed across the band (`-7.5e-7 … +7.3e-7`), while the lossy
  control is one-signed and in the range `-0.029 … -0.34`.
* **Its cause is unattributed.** This leg does not guess one. A natural next step is to save the
  reference monitors as well and compare the reference's flux at the reflection and transmission
  planes.

**Negative control.** The archived config declares the control truthfully as lossy, so the
report correctly *drops* `V2-a` there. The control re-evaluates `V2-a` on an in-memory copy that
claims the box is lossless, and it **fails with error `0.340`**. That is about `4.5e5` times the
lossless floor. So the balance does tell the two boxes apart, but not at the declared tolerance.

Because `V2-a` failed on the slab, every `R`/`T` leaf of the slab cases is `unchecked` in the
report, even though `V2-b` passed there. A failed covering check blocks promotion. That is
existing behaviour, and this leg did not change it.

Two things about the audit itself:

1. The audit's `covered`/`open` column comes from a **name table** in `src/coverage_audit.py`.
   `energy_residual` was already `covered` there by name. What moves on real labels is the
   "wired but not granting" list, which went from 2 to 0. The `covered` counter cannot move unless
   that table is edited, and that file is outside this leg's write scope.
2. **`energy_spread` cannot honestly be closed by this leg.** It does not come from a closed-box
   balance. It is `src/leg7_campaign.py`'s spread of delivered energy across swept Bloch phases,
   in the **parked ASM route** (leg 7, part 2 rejected; measured `0.39` relative against a `0.002`
   tolerance). A non-empty closed box measures a different quantity. Naming a new readout
   `energy_spread` so that the audit counts it would be granting by name, which C4 forbids. The
   plan's premise for this field (§4 of the leg-11 doc) is mistaken. The field belongs with the
   other `settled` ASM fields (`forward_total`, `backward_total`, `delivered_total`), and that
   reclassification is the leg-11 owner's call.

## 4. Defect this leg introduced

The box run's readout carries a top-level `negative_control[]` list with numeric `error` and
`tolerance` entries. `error` is a new field family that no rule in `src/coverage_audit.py`
matches, so `checks/test_coverage_audit.py::test_c3_every_open_physics_gap_is_assigned_and_costed`
now **fails** ("error: emitted but unclassified"). The audit is working as designed here: it
refuses to guess. The run record is not edited or deleted. The fix is one rule in
`src/coverage_audit.py` (`error` → `statistic`, not-applicable), and that file is outside this
leg's write scope.
