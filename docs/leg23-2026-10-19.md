### Occupied double-count demonstration (final run)

The successful new-2 report supplies base subtotal **1,122,914,344** bytes, live
component **203,555,840** bytes, and total prediction **1,193,134,174** bytes
(including the modal packet). Occupied admission measured a live allocation of
**12,883,849,216** bytes; the held tensor alone was **12,680,293,376** bytes.
The worker's pre-admission read was 12,883,848,704 bytes: the 512-byte difference
is why the reconstruction uses the observed reservation-call live value.

```text
occupied subtotal = 1,122,914,344 - 203,555,840 + 12,883,849,216
                  = 13,803,207,720
headroom          = 8,388,608 + ceil(13,803,207,720 / 20)
required          = 13,803,207,720 + headroom
                  = 14,501,756,714
```

This exactly equals the actual occupied refusal's `required_bytes` and the
separately observed `memory_reservation_bytes`. The same admission's actual
CUDA free-memory query was **507,183,104** bytes with **12,883,849,216** bytes
live. `floor(0.8 * 507,183,104) = 405,746,483`, exactly the printed limit.
Thus the live allocation enters the required subtotal with headroom and is
already absent from the free memory used for the limit. The unoccupied solve's
reserved peak is only 1,145,044,992 bytes. This demonstrates the over-conservative
comparison without claiming that the occupied device had room to run the solve.
The historical 14,527,222,826-byte diagnostic is preserved in the leg-19 record;
the present value reflects a different measured holder and free-memory state.

## Interpretation and limits

Admitted rows use the worker's original `solver_report.memory_reservation_bytes`.
Refused rows have no returned plane report: the observation wrapper records the
reservation call that refused, then reads the model's process prediction with
only the CUDA capacity comparison bypassed. It rethrows the original refusal,
so no refused worker proceeds to field allocation or a solve. The measured
reserved peak of the occupied worker includes its resource-pressure holder.
Those refused rows therefore do not measure the peak of a simulation that was
never executed. Their margins describe the observed refusal process, not a
counterfactual successful solve.

The exact double-count reconstruction removes the new-2 base live component
from its subtotal, substitutes the live allocation observed at occupied
admission, and reapplies the unchanged 8 MiB plus 5% headroom. This arithmetic is
a diagnosis of the current model. It neither changes reservation semantics nor
proposes a replacement formula. CUDA free-byte queries establish the other half
of the duplication: the live allocation has already reduced the free memory
used to calculate the actual refusal limit.

The negative control demonstrates a relation failure without allocating a large
GPU tensor. The temporary-repository control demonstrates that the real legacy
OOM branch restores its target and returns 59 without another worker. Neither
control induces a real GPU OOM or a reversion in the shared fork, and this leg
does not claim either happened. The measurements do not establish a universal
no-OOM guarantee, behavior on other GPUs, other geometries, adjoint workloads,
or the unmeasured full-device calibration. W3's future implementation has not
been verified; only the gate's independence from the incremental diagnostic is
covered by the added synthetic test.

Only the LEG 23 tests are required and were run; the whole repository suite was
not rerun. No fork source was changed. The leg-19 campaign's historical envelope
repair, numerical-equality gates, and other C1-C5 decisions are not reaccepted
by this relation driver. Independent wave review, steward reacceptance, merge,
and workspace retirement remain the orchestration roles' work.
