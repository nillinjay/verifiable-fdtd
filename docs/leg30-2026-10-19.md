## Classification rule and its effect on the audit

`src/coverage_audit.py:170` defines `classify_readout`. Every discovered
`runs/*/readout.json` must be a readable JSON object and meet exactly one selected
contract. A nonempty string `policy` is mandatory for contemporary readouts.
An explicit `readout_kind: "diagnostics"` selects the diagnostics contract and
requires a nonempty string `readout_reason`. The diagnostics declaration is
authoritative; its content is not sent to the pipeline verifier. Otherwise the
readout must have the exact ordered stage list from `verification.STAGES`.
An optional explicit pipeline kind must be `"pipeline"`; unknown or null kinds
are rejected rather than guessed. Pipeline verification still enforces stage
implementation sources, cases and all its existing requirements.

The pipeline stages remain F1 (structure), F2 (mesh), F3 (source), F4 (monitors),
F5 (run) and F6 (readout). `src/verification.py` was not changed. The existing
headline verification, analytic-case labels and convergence guard are unchanged
for valid pipeline inputs.

`discover_runs` remains list-compatible for existing callers, but returns only
pipeline paths and attaches the diagnostics records to the inventory. Those
records retain the directory, policy and reason. `render` reports their count
and lists each one. Diagnostics never contribute headline rows, families or
pipeline-run counts. Classification happens before the existing audit-policy
exclusions, so even an excluded audit ledger cannot conceal an invalid shape.

The two existing audit drivers convert the discovery result to a plain list to
filter their own directory. That discards attached diagnostics metadata. Within
this leg's fixed write set, rendering recovers the diagnostics from the supplied
paths' archive roots. An empty plain driver list uses the launcher's
`RUN_DIR_ABS` root, or the repository root for a dry run. Explicit discovery
results, including empty synthetic inventories, retain their own context and do
not use that fallback. A dedicated test covers the diagnostics-only driver case.
The drivers themselves were not edited.

Unclassifiable readouts raise `ReadoutClassificationError`, naming the directory
and field. The old aggregation behavior of swallowing readout failures into an
unreadable row was removed: a bad readout is an audit failure. Reusing an
inventory also revalidates its diagnostics, so changing a diagnostic after
discovery cannot make a malformed artefact disappear. The new read-only CLI,
`.venv/bin/python src/coverage_audit.py [repository-root]`, reports contract
failures to stderr and exits **1**; valid inventories exit **0**. The existing
LEG 11 driver also propagates discovery/verification failures as nonzero exits.

At `src/leg24_graded_modal.py:139`, the driver now initializes its report with
the configured `policy`, `readout_kind: "diagnostics"` and the reason:

```text
Modal default-path identity and uniform/graded comparison; cases are worker
diagnostics, not an F1-F6 pipeline readout.
```

Those fields are present in incremental worker readouts as well as the final
readout. The numerical comparison and exit-code logic are unchanged.
