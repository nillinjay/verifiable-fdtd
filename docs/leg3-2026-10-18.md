## The laws: where they come from, and what each one assumes

The reference projects are read-only and are never imported at run time, so the laws are
**transcribed by citation**, unchanged, into `src/analytic_cases.py`:

| case | source | scope, as stated in this repository |
|---|---|---|
| `V1-fresnel` | reference project `src/run_canary.py`, function `analyze`, branch `interface` | one planar interface, **normal incidence**, vacuum on both far sides, wavelength independent |
| `V1-airy` | reference project `src/run_canary.py`, function `analyze`, branch `slab` | one planar slab, optical thickness `2.1` micrometres, **normal incidence**, lossless and non-dispersive |

Criterion C3 requires the law's scope to match the configuration actually run. Both matches are
declared in the config, before the run, in a `scope_match_reason` field. Both hold: the copied
builder places a half-space (`interface`) and a single non-dispersive slab (`slab`) behind a one-way
plane source at normal incidence, with vacuum on the incident side.

## The tolerance, and what kind it is

Criterion C2 requires every tolerance to state whether it is a **physics** tolerance or a
**discretisation-limited floor**, and to say when it is inherited.

Both cases use `0.01` absolute, declared as a **discretisation-limited floor**, and both say
`INHERITED, not measured here`: it is the reference project's A1 canary threshold, which that
project requires at `ppw >= 20` for index `1.5` and `3.5`. It is the achievable floor at that
resolution. It is not a claim about the physics, and it is not this project's own measurement.
This leg reports the measured error next to it, so a reader can judge the margin: the Fresnel case
sits `9.1` times inside the threshold, the Airy case `1.2` times inside it.

## The negative control

The controller copies the readout in memory, adds `0.25` to one measured transmittance point, and
runs the same check code. `V1-fresnel` then reports `failed` with error `0.25` against tolerance
`0.01`, and the process exits `1`. The unperturbed `V1-airy` case still passes, so the control
shows the failure is caused by the perturbation and not by a broken checker. **The source run files
are never written**, and a unit test asserts that the input readout is unchanged after the call.

## What could not be done, and what it costs

1. **Two of the four registered cases were not delivered.** `V1-slab-mode` needs a
   symmetric-waveguide configuration with a modal port; the copied builder does not construct one.
   `V1-mie` needs a sphere and a closed-surface flux. Each is a separate registered step.
2. **The tolerance is inherited, not earned.** Criterion C2 is satisfied by declaring that honestly,
   but this project has not yet measured its own convergence floor for these cases. That is what
   `V3` (the convergence ladder) will supply. Until then, `0.01` is a borrowed number.
3. **`verified` covers the R and T curves only.** It says those points passed a named closed-form
   law on that case. It says nothing about any other number, and it is not quantitative accuracy
   for the guided fixtures, which no analytic case covers.
4. **Leg 2 has one open coverage wart**, recorded in its own verdict: the field `energy_residual` is
   labelled `unchecked` although `V2-a` is its check. Still open; it does not affect this leg.
