# LEG 35 — a missing reference contract is a declared `65` refusal (2026-10-20)

LEG 28 shipped four frozen tests and three of them were red on `main` by design. This leg
satisfies those tests by fixing the pre-flight only. The test file was not edited, and no
reference schema was invented.

## The defect

`checks/pre_environment.py:99-100` entered the reference branch like this:

```python
if config['kind'] == 'alignment' or config.get('reference'):
    from reference_contract import load_reference
    family = config.get('artifact_family', 'staircase')
    try:
        load_reference(root / config['reference'], family)
    except (FileNotFoundError, ValueError, KeyError, TypeError, IndexError) as error:
        raise SystemExit(f'{family} reference unavailable/invalid: {error}; '
                         'no simulation allowed; see output/lumerical-reference-contract.md')
```

The import sat **outside** the `try`, and `reference_contract.py` does not exist in the
repository. Any config with `kind: alignment` or a `reference` field therefore died with a bare
`ModuleNotFoundError` traceback and exit `1`. The asymmetry is what made this a defect rather
than a missing feature: an **invalid** reference already had a careful refusal
(`:102-105`), but the **missing module** never reached it.

## The change

`checks/pre_environment.py:29` adds `import sys` (needed to write the refusal to stderr).
`checks/pre_environment.py:100-119` replaces the unconditional import with three steps:

1. build the list of config fields that require the contract
   (`kind: alignment`, `config field \`reference\``, joined with `and` when both apply);
2. attempt the import inside a `try` that catches `ModuleNotFoundError` **only**;
3. if `error.name != 'reference_contract'`, re-raise — a `ModuleNotFoundError` raised *inside*
   a real `reference_contract` is a genuine contract error and is not masked. When the missing
   name is the contract itself, print the refusal and `raise SystemExit(65)`.

The full refusal is:

```text
reference contract module is missing: cannot import reference_contract (required by kind: alignment); no simulation was run
```

and, for a `reference` field on an `audit` config:

```text
reference contract module is missing: cannot import reference_contract (required by config field `reference`); no simulation was run
```

The invalid-reference branch is untouched: same `except` tuple, same message, same place. The
two refusals remain distinguishable because the missing-module message contains none of the
invalid-reference vocabulary (`reference unavailable/invalid`, `invalid reference`,
`reference unavailable`), while the invalid branch keeps that vocabulary and its pointer to
`output/lumerical-reference-contract.md`.

## Note on the "invalid reference also exits 65" premise

`checks/pre_environment.py:121-125` still raises `SystemExit(<message string>)` for an invalid
reference, which—when `pre_environment.py` is invoked directly—exits `1`, not `65`. Through
`tools/run.sh`, `tools/launch.py:175-176` wraps every non-zero pre-flight result as `65`, so the
launcher-visible code is `65`. LEG 28's record already called out this nuance. This leg left the
invalid-reference branch byte-for-byte unchanged, per stop condition 3 ("keeps its own message
and its own code"); the missing-module branch intentionally uses the integer form because the
frozen test asserts the direct process exit.
