## What the audit found, in the order it matters

### 1. Two fields have a check that does not grant it

`energy_residual` and `empty_reflection_floor` are both covered by `V2-a`/`V2-b` — and both are
labelled `unchecked`. **This is a wiring gap, not a missing check.** `STATUS.md` already carried
"`energy_residual` is labelled `unchecked` although `V2-a` is its check" as an accepted wart; the
audit makes it mechanical and shows it is two fields, not one. No new physics is needed to close it.

### 2. Six fields are waiting on the readout-definition ledger (`S4`)

`J`, `P_up_reduced`, `P_in_reduced`, `unit_mode_flux_reduced`, `reference_power_reduced`, `eta_lat`.
`S4` is already registered and already on the critical path, so these six need no new leg — but they
carry **the largest single unresolved term in the project** (`5.6` percentage points in the
transition-region loss, and a radiation strength `~40 percent` above the paper's design, now recorded
as **unattributed**).

### 3. Four fields need an analytic case that does not exist yet

`zero_order_efficiency`, `zero_order_efficiency_a`, `zero_order_efficiency_b`,
`zero_order_forward_power`. A grating single-order efficiency case would cover all four at once. **No
leg is registered for it**; this is a proposal, not a plan entry, and it would cost roughly
`0.5 GPU-h` plus the derivation work.

### 4. Two fields need `V2` extended to a non-empty closed box

`energy_spread` and `energy_spread_relative` — the balance is checked today only in an empty domain.

### 5. One field needs a slab-mode analytic case

`launch_neff`. It is the modal launch's own effective index; nothing checks it, and a known stack has
a closed form.

### 6. What is *not* a gap

Eight physics fields are not gaps because a decision closed the question — the `S1` angle-drift bound
(`drift_deg`, `k_fixed_per_um`), the parked ASM route (`forward_total`, `backward_total`,
`delivered_total`), and the cited-input values from `S2` (`model_peak_eta_lat`,
`reconstruction_error`, plus the `launch_scores` diagnostic). The audit names the reason for each, so
"no check" and "not a gap" cannot be confused.

## A defect this leg hit and fixed

The first run through `./tools/run.sh` failed the preflight gate with `Every run needs a step number
in task` — a **negative control working**: the gate refused a config with no `task` field. Then the
run **succeeded while reading zero runs and writing a readout full of zeros**. The launcher runs a
script from the run's source **snapshot**, which by design excludes `runs/`, so the audit was looking
for archived runs inside the snapshot and finding none.

**The fix:** the code comes from the snapshot, the data comes from the repository the run directory
belongs to (`RUN_DIR_ABS`'s grandparent). `PARITY_CONFIG` is *not* usable for this — the launcher
points it at the run's own archived config.

**The lesson worth keeping:** a run that completes with exit 0 and a full readout can still have read
nothing. `runs_read: 0` was in the readout and would have been easy to skim past. The audit now
reports that number, and it is a headline.

## Cost and limits

CPU only, under a second; no simulation, no GPU, no fork change. **The audit's limits are its rules
table**: it classifies by field *name*, so a field that means something different in a future leg
would be classified wrongly until the table is updated. That is why stop condition 1 exists and why
the "unclassified" count is printed — today it is `0`, and a future non-zero is the signal.

## What is *not* claimed

* No label was changed. The audit does not make anything more verified, and it is not acceptance.
* The coverage table is the auditor's classification of *roles*, not a physics judgement. Where a
  field's meaning could not be established from this repository, it is named in the unclassified
  report rather than guessed.
* `4 of 25` is a count of *fields*, not of numbers: one field such as `T` carries a curve of 82
  points. The audit counts both, and reports the field count as the headline.
