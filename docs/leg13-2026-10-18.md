## C1 — how the ledger is checked

**Scope.** Every (policy, physics field) pair that the archived readouts report, where "physics" is
leg 11's own classification (`coverage_audit.classify`). The scope is pinned to the runs leg 11
inventoried (run ids up to and including its audit run `20261018T131254Z-619690`, 33 runs) plus this
leg's own runs. Runs written later by legs 12 and 14, running in parallel, are **listed but not
judged** — their declarations belong to their own legs. At the final ledger run they contributed `11`
pairs (`leg12-closed-box-v1`: `R`, `T`, `empty_reflection_floor`, `energy_residual`,
`reference_power_reduced`; `leg14-*`: `zero_order_efficiency` and its two per-angle variants,
`zero_order_forward_power`, `launch_neff`), and this leg's own controls run contributed the `13` pairs
of its own schema (`R`, `T`, `energy_residual`, `empty_reflection_floor`, `reference_power_reduced`,
`forward_flux_reduced`, `backward_flux_reduced`, `symmetric_ratio_max_deviation`,
`oneway_ratio_max_deviation`, `deviation`, `margin`, `frequencies_used`, `frequencies_dropped` — the
last four are the control's own bookkeeping and are classified as statistics, not physics).

**Where a definition comes from.** Either the run's own mirrored declaration (leg 5 onwards; `5`
pairs, plus this leg's own controls run) or `units_ledger.READOUT_DEFINITIONS` (`43` entries). Each registry entry names the function it
was recovered from. The definitions were read from the code paths that produced the numbers:
`parity.project_for` + `parity.spectra` (legs 2 to 5), `run_b9_native_shape_n8.scene` +
`leg1_objective.main` / `leg1_forward.main` / `leg10_true_2d.main` (the N8 fixture),
`leg7_campaign.build_project` (legs 7, 9), `coupling.lateral_overlap` (leg 6).

**What "mechanically" means here — three layers.**

1. *Presence and form.* `units_ledger.audit_definitions` requires a unit from the closed vocabulary
   and non-empty `plane`, `span`, `normalisation`, plus a `source`. A recovered entry may not contain
   the text `UNKNOWN`; an honest unknown must be marked `status: unknown` with a reason, and is
   counted separately so it can never pass for a definition.
2. *Geometry against the built project.* Leg 5's ledger was `declared-only`: it could not check that a
   declared plane was the plane the run used. This leg closes that for every monitor-based number.
   `units_ledger.DECLARED_GEOMETRY` states each monitor's normal, centre and size as numbers; for
   every in-scope run, `leg13_ledger.build_family` rebuilds the project **from that run's archived
   `config.input.json`** with the same builder the run used, and `cross_check_monitor` compares.
   A snapped plane may sit half a cell from its nominal position along its normal; everything else
   must agree to `1e-9` um. Result: 37 monitor-based pairs, `207` comparisons, `0` disagreements.
3. *Negative controls (all must fail, all did).* Registry entry for `J` removed -> `missing=6`;
   `span` of `P_in_reduced` blanked -> `missing=5, invalid=1`; an invented field observed ->
   `missing=1`; the declared near plane moved to `x = -0.70` um and the declared transmission span set
   to `1` um -> both fail.

* It is **a limit of the comparison**, as the `S4` row's fallback says. It is not a result about

* **No number in this repository measures it.** Every guided fixture here (N8, G8) starts at the

* **Closing it needs a new simulation campaign** (a vendor run with a recorded plane, span and basis,

## C4 — attribution before conclusion

**The `5.6 pt` term.** Attributed to the **readout definition**, specifically to an unmatched and
partly unrecorded normalisation basis — not to physics, not to the paper. The paper does not enter
this term at all; it is ours against the vendor's.

**The `~40 percent` radiation-strength term.** Attributed from the material, and the attribution is
**not** "readout definition" and **not** "physics of this solver":

* The `4.15-4.33 Np/mm` value belongs to the **predecessor project's separate FDTD
  implementation**. `$PARITY_REF` `plan.md` step 26b withdrew it for the reference solver line
  ("there is no 40 percent excess in this solver"), which measured `2.87-3.05 Np/mm`.
* **That `2.87-3.05` sits near the paper's `3 Np/mm` is not used as evidence** (owner's rule: agreeing
  with the paper is not evidence of correctness). The evidence used instead is a physical bound:
  `alpha <= -ln(T_far) / (2L)`, because every loss other than radiation can only lower `T_far`. With
  the recorded `T_far = 0.0238` and `L = 550.8` um this gives `alpha <= 3.393 Np/mm`, which
  **excludes** `4.15-4.33` for that solver line, independently of the paper. Assumption stated: a
  uniform (unapodized) `alpha` along the grating.
* **No number in this repository measures `alpha`** (N8 is eight periods, not a decay length).

**Request to the owner, done by the main session after this leg:** `plan.md` and `STATUS.md` carried
"radiation strength `~40 percent` above the paper's design, unattributed". The material attributes it
to the predecessor's separate implementation and the reference project withdrew it on 2026-10-13.
`STATUS.md` and the one-pager now say so; `plan.md`'s `S4` row keeps the original question, since
`plan.md` is the record of what was asked.

**The paper's own normalisation plane and span** remain `X`, as `S4`'s row already says. This leg
did not invent one.
